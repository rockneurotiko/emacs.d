Beacon — batch kmacro, not multi-cursor

Skill Multi-place edits · Mission Replace query-replace + multiple-cursors

What beacon is, what it isn't

"BEACON is the state used for applying kmacro to multiple places quickly. It's kinda like multiple-cursors, but it works differently."
— meow tutorial

You currently reach for query-replace and multiple-cursors. Beacon replaces both — but you have to drop the multiple-cursors mental model to use it well. Beacon doesn't put a live cursor at every match. It does this:

  1. You define a scope (a secondary selection — like a region, but persists while you do other things).
  2. Inside that scope, every cursor-creating motion drops fake cursors at all the matches.
  3. You then enter insert state. Meow starts recording a kmacro.
  4. You type your edit. Just at your real cursor. You don't see anything happening at the fake ones.
  5. You exit insert state. Meow plays the recorded kmacro at every fake cursor.

That last step is the mental shift. With multiple-cursors you watch the edit happen N times in parallel. With beacon you record one edit and let meow apply it N times. The result is the same; the model is different.

Your keys for this

From your config (settings/meow-settings.el):

  • G meow-grab — create the secondary selection from the current selection. This is the gateway to beacon.
  • R meow-swap-grab — swap your current selection with the secondary selection.
  • X meow-sync-grab — sync the secondary selection's content to the current one.

BEACON state activates automatically when your cursor moves into the secondary selection. You don't toggle it manually.

BEACON has its own keymap — the one rule you must know

Only i, a, and c trigger the kmacro recording from BEACON. This is explicit in meow's state diagram: BEACON ──i/a/c──> INSERT. The commands I (open-above) and A (open-below) only transition from NORMAL, not BEACON. If you press I inside BEACON nothing useful happens. Use i instead.

The motions that create fake cursors

Once you're in BEACON state, these movement commands place a fake cursor at every match within the secondary selection:

  • w / W — fake cursor at the start of every word/symbol
  • m / M — fake regions on every occurrence of the same word/symbol under cursor
  • v / s — fake regions on every match of a regexp
  • f / l — fake cursors on every matching char
  • e — fake regions on every N lines (N = number of lines in your selection)
  • j — fake cursors at every indentation start

For your day-to-day the big two are M (every occurrence of this symbol — your rename move) and e (per-line operations).

Line selection: always use e, not .l

e (meow-line) is an expand-line selection type. Digits after it expand the count cleanly: e4 = 4 lines. .l is a thing-selection — a structurally different family. Its digit behaviour is not the same. For counting lines, always use eN. See four-selection-families reference.

The canonical workflow

The five-step shape

  1. Select scope. Build a selection covering the area for edits. e.g. .d for "this function", or e4 for "these 4 lines".
  2. Grab it. G — turns it into a secondary selection. Cursor returns to where it was.
  3. Move into it. Move your cursor inside the highlighted secondary selection. BEACON state activates automatically (check your modeline).
  4. Drop fake cursors. Press a motion: M for every occurrence of this symbol, e for per-line, etc.
  5. Edit + exit. Press i, a, or c (not I/A). Type your edit. Press ESC. Meow replays your edit at every fake cursor.
The most common mistake: forgetting step 3. After G, your cursor is back at its original position — outside the secondary selection. You must move into the highlighted region before BEACON activates. If M doesn't drop fake cursors, this is why.

Drill

Setup

Open a scratch buffer. Paste:

defmodule Calculator do
  def add(a, b), do: a + b
  def sub(a, b), do: a - b
  def mul(a, b), do: a * b
  def div(a, b), do: a / b

  def helper_one(x), do: x + 1
  def helper_two(x), do: x + 2
end

Rep 1 — rename every a to x in the first four defs

  1. Position cursor on the first def add line.
  2. e4 — select 4 lines (the four math defs). Use e, not .l.
  3. G — secondary selection. Those 4 lines highlight in a different shade. Cursor returns to where it was.
  4. Move cursor into the highlighted block. BEACON state now active (check modeline).
  5. Put cursor on any a. Press M — fake regions appear over every a in the scope.
  6. Press c, type x, press ESC.
  7. Every a becomes x in scope. The helper_* defs below are untouched.
  8. z to undo.

Rep 2 — add @spec above every def in the scope

The kmacro power multiple-cursors doesn't have: the recorded edit can include movement and newlines, not just inserted text.

Important: I (open-above) does not work here — only i/a/c start kmacro recording from BEACON. The trick: i enters INSERT at the start of an e-selected line (column 0). Typing content then Enter pushes the original line down — same visual result as open-above, built from BEACON-legal primitives.

  1. Cursor on the first def add line.
  2. e4 then G — grab 4 lines as secondary.
  3. Move cursor into the secondary selection.
  4. e — fake regions per line.
  5. i — enter INSERT at the start of the region (column 0 of each line).
  6. Type @spec todo, then press Enter.
  7. Press ESC — meow replays the recording. Every def now has a @spec todo line above it.
  8. z to undo.
If Method A doesn't behave cleanly, use the general kmacro escape hatch: after fake cursors are placed, press F3 to start recording (this bypasses the BEACON keymap restriction), do any edit you want including I, then press F4 to end and apply. This is the tutorial's "generally" path.

Rep 3 — the query-replace replacement

Your old habit: narrow region, M-%, type from, type to, !. Five steps including two prompts.

The beacon version, to rename every b to y in the math defs:

  1. e4G — scope
  2. Move in. M on a b — fake regions on every b.
  3. c y ESC — done.

Three steps, no prompts. Visible scope. Undoable as one action.

When to still reach for query-replace or LSP rename

  • Regexp replacements. Beacon's M matches a literal symbol. M-% with regexp still wins for "swap order of two captured groups."
  • Multiple files. Beacon is one-buffer. Project-wide rename → LSP rename or project-query-replace-regexp.
  • Confirmation per match. Beacon is all-or-nothing after ESC. M-% still wins when you want to skip some matches.

Win condition

  • You can rename a symbol within a function in these keystrokes: .dG, move in, place cursor on symbol, Mc, type new name, ESC.
  • You catch yourself reaching for M-% on a scoped rename and switch to beacon instead.
  • You can explain: "it's a recorded kmacro played at fake cursors, not parallel edits."
